# Integration Guide

## Overview

This guide covers how to integrate AI Brand Creator's components and features into your application.

## Getting Started

### Installation

First, install the required dependencies:

```bash
npm install @supabase/supabase-js @google/generative-ai
```

### Environment Setup

Configure your environment variables in `.env`:

```env
NEXT_PUBLIC_SUPABASE_URL=your_supabase_url
NEXT_PUBLIC_SUPABASE_ANON_KEY=your_supabase_anon_key
SUPABASE_SERVICE_ROLE_KEY=your_service_role_key   # server-side only
KEY_ENCRYPTION_SECRET=base64_32_random_bytes      # openssl rand -base64 32; users add their own OpenAI key in Settings
```

## Database Integration

### Supabase Setup

1. Create required tables:
```sql
-- content_items table
CREATE TABLE content_items (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  title text NOT NULL,
  type text NOT NULL,
  url text NOT NULL,
  metadata jsonb DEFAULT '{}'::jsonb,
  created_at timestamptz DEFAULT now(),
  updated_at timestamptz DEFAULT now(),
  user_id uuid
);

-- voice_profiles table
CREATE TABLE voice_profiles (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name text NOT NULL,
  voice_id text NOT NULL,
  settings jsonb DEFAULT '{}'::jsonb,
  created_at timestamptz DEFAULT now(),
  user_id uuid
);

-- image_assets table
CREATE TABLE image_assets (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  title text NOT NULL,
  url text NOT NULL,
  metadata jsonb DEFAULT '{}'::jsonb,
  created_at timestamptz DEFAULT now(),
  updated_at timestamptz DEFAULT now(),
  user_id uuid
);
```

2. Enable Row Level Security (RLS):
```sql
ALTER TABLE content_items ENABLE ROW LEVEL SECURITY;
ALTER TABLE voice_profiles ENABLE ROW LEVEL SECURITY;
ALTER TABLE image_assets ENABLE ROW LEVEL SECURITY;
```

## AI Integration

### OpenAI Setup

The key stays on the server. Use the shared helpers (Responses API for text, Images API for images):

```tsx
import { createResponse, generateImage } from '@/lib/openai';

const text = await createResponse({ input: 'Analyze this brand', json: true });
const [image] = await generateImage({ prompt: 'Logo concept' });
```

From the browser, call `POST /api/ai/generate` or `POST /api/ai/image`.

### Voice Generation

```tsx
import { generateVoiceOver } from '@/lib/services/voice';

// OpenAI text-to-speech (Realtime API); voiceId is a built-in voice such as "marin"
const audioBlob = await generateVoiceOver(text, 'marin');
const audioUrl = URL.createObjectURL(audioBlob);
```

### Image Generation

```tsx
import { generateBrandImages, transformImage } from '@/lib/services/openai-images';

// OpenAI Images API (gpt-image-2.6): generate new concepts, or edit an existing image into variations
const created = await generateBrandImages(prompt);
const variations = await transformImage(imageUrl, prompt, style);
```

## Performance Optimization

### Data Caching

Cache analysis results:

```tsx
const cachedAnalysis = localStorage.getItem('brandAnalysis');
if (cachedAnalysis) {
  return JSON.parse(cachedAnalysis);
}

const analysis = await performAnalysis();
localStorage.setItem('brandAnalysis', JSON.stringify(analysis));
```

### Lazy Loading

Use dynamic imports for heavy components:

```tsx
import dynamic from 'next/dynamic';

const VisualIdentityAnalyzer = dynamic(
  () => import('@/components/visual-identity-analyzer'),
  {
    loading: () => <LoadingSpinner />,
    ssr: false
  }
);
```

## Security Considerations

### API Key Protection

Store API keys in environment variables and never expose them in client-side code.

### Data Validation

Validate all user inputs:

```tsx
function validateInput(data) {
  if (!data.businessIdea) {
    throw new Error('Business idea is required');
  }
  // Add more validation as needed
}
```

### Access Control

Implement proper authentication and authorization:

```tsx
function checkAccess(userId, resource) {
  // Check if user has access to resource
  return hasPermission(userId, resource);
}
```

## Troubleshooting

### Common Issues

1. **Component Not Rendering**
   - Check if all required props are provided
   - Verify API keys are set correctly
   - Check for console errors

2. **Analysis Fails**
   - Verify API rate limits
   - Check input data validity
   - Review error messages

3. **Performance Issues**
   - Implement lazy loading
   - Use data caching
   - Optimize asset sizes

## Security: rotate keys that were committed earlier

Git history still contains the original `.env` (commits `2ff6c7f` and `ba0d981`) with **live** credentials: Gemini, ElevenLabs and Recraft API
keys and the Supabase anon JWT. Removing a file from the working tree does not remove it from history, so treat every one of those
values as compromised:

1. Revoke and regenerate the Gemini, ElevenLabs and Recraft keys in their dashboards (the app no longer uses these providers at all).
2. Rotate the Supabase anon and service-role keys (Project Settings → API → JWT secret rotation) and update `NEXT_PUBLIC_SUPABASE_ANON_KEY`,
   `SUPABASE_SERVICE_ROLE_KEY` and your hosting environment.
3. Optionally purge the history (`git filter-repo --path .env --invert-paths`, then force-push and have every collaborator re-clone).
   Rotation is the part that actually protects you; a purge alone does not, because the old values may already have been copied.

The app now needs no third-party AI key on the server: each signed-in user supplies their own OpenAI key in **Settings → OpenAI**.
